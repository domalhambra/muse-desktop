# mMac M4b (the proof work) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers-extended-cc:subagent-driven-development (recommended) or superpowers-extended-cc:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status:** planned on 2026-10-23, after M4a merged into `extensions` as PR 9 (`f5715d4`) and PR 10 (`d5a627c`). Branch `mac-m4b`, in the worktree `.cache/worktrees/mac-m4b`. The first live session ran on 2026-10-23 and 2026-10-24. Its failures are fixed in the background ("Fixes after the first session"). The background gate passes: typecheck, Vitest (217 tests), build, format, integration, headless, MuseBackend (61 tests), MuseKit (392 tests) and `build-for-testing`. `mac/scripts/ui-tests.sh 3` and the rest of the live run wait for the end, by Dom's request on 2026-10-24.

**Goal:** Prove on screen what M4a proved in unit tests. M4b writes UI tests for the seven M4a features, runs every UI test three times in a row, and makes the live isolated run of M2, M3 and M4a with Dom at the Mac. M4b adds no features.

**Architecture:** The UI tests drive the Debug build through XCUITest against the fake backend `mac/Fixtures/fake-backend.mjs`, as M2's and M3's tests do. The live run launches the same Debug build once, under a temporary home, with the echo provider and a throwaway Git project. Claude drives the run with computer use on mMac's window only, and Dom answers the system prompts.

**Tech Stack:** XCUITest, XcodeGen, `mac/scripts/ui-tests.sh`, Node (the fake backend), the installed `muse` CLI with the echo provider.

## Scope

The M4a plan's "Carried into M4b" (`docs/superpowers/plans/2026-10-22-mmac-m4a.md`, the last section with that name) is the source for every check. This plan does not repeat its text. It names the parts:

- "The UI tests": what each new UI test covers.
- "The live isolated run": M3's Task 16 checklist and notes, then the M4a feature checks.
- "Runtime checks from the app tasks": the checks only a running mMac shows, A5 and A6 included.
- "Open items from the M4a reviews": recorded, not fixed (Dom's decision).

## Hard rules

- Never read, list or write `~/.config/muse/`. Every launch uses a temporary `HOME`, `CFFIXED_USER_HOME`, `MUSE_HOME`, `XDG_CONFIG_HOME`, `XDG_DATA_HOME`, `XDG_STATE_HOME` and `ZDOTDIR`, with `MUSE_DESKTOP_TEST_PROVIDER=echo` and `MUSE_NO_AUTO_UPDATE=1`, and `MMAC_DATA_FOLDER` inside it.
- Never read or write the Keychain item `com.domalhambra.mmac.bridge-token`. Never run `security find-generic-password -w`. Claude never types a password. The UI tests use `MMAC_TOKEN_STORE=memory`. The live run uses `MMAC_KEYCHAIN_SERVICE=com.domalhambra.mmac.test`, and deletes that item at the end.
- Dom's defaults domain `com.domalhambra.mmac` stays unchanged. The UI tests and the live run use `MMAC_DEFAULTS_SUITE`.
- UI-test screen capture stays off. Screenshots show mMac's window only.
- Never launch, quit or signal `/Applications/Muse Desktop.app`.
- A Terminal window that the Muse Code button opens runs with Dom's own environment. Ask Dom before that click.
- Never push upstream. Never edit `src/main/`. Commits use `area: summary` with the Opus co-author line. Dom merges.

## Task 1: The UI tests for the M4a features

**Goal:** One UI test per M4a feature, against the fake backend, with each test finding controls by accessibility identifier.

**Files:**

- Modify: `mac/mMacUITests/MMacUITests.swift`, `mac/Fixtures/fake-backend.mjs`
- Modify only if a test needs an id that is missing: files in `mac/mMac/`

**Acceptance Criteria:**

- [ ] The fake backend answers the M4a methods the tests call: `compact`, `export`, `attachments`, `remove-attachment`, `voice`, `cancel-voice`, `terminal`, `cli-terminal`, and `send` with `attachments`. Its `protocol` stays equal to `HEADLESS_PROTOCOL`.
- [ ] Seven new tests, one per feature:
  - ⌘K: open, filter, choose a conversation, see the empty state, close with Escape.
  - Pins and archives: pin from the hover button, archive and restore from the context menu, the Archive toggle.
  - Export: with `MMAC_TEST_EXPORT`, the file is written with mode 600 and the toast shows.
  - Composer commands: the slash popup, Tab, `/help`, `/rename`, and `/plugins` refused with the draft kept.
  - Mentions and attachments: the `@` popup inserts a path. `MMAC_TEST_ATTACHMENTS` adds chips, and a chip's remove button removes it.
  - Voice: the button and the status pill follow the states the fake backend allows, and ⌥V types no character. The microphone does not run in a test.
  - The inspector footer: the three buttons show, and they are enabled with a project and disabled without one. The test does not click them.
- [ ] No test opens Terminal, Finder, a save panel, an open panel or the microphone.
- [ ] `xcodebuild build-for-testing` succeeds.

**Verify:** `cd mac && xcodegen generate && xcodebuild build-for-testing -project mMac.xcodeproj -scheme mMac -destination 'platform=macOS' -derivedDataPath ../.cache/mmac` → `** TEST BUILD SUCCEEDED **`. Task 2 runs the tests.
